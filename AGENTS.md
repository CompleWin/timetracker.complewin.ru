# Онбординг агента

Этот файл для ИИ-агентов, которые пишут код в репозитории. Людям те же правила нужны при доработках: [CONTRIBUTING.md](CONTRIBUTING.md) ссылается сюда.

SimpleTimeTracker: трекер времени по задачам и проектам. Вход через Telegram, синк с Notion, Telegram-бот, PWA. Один Cloudflare Worker отдаёт API и фронтенд, данные лежат в D1.

## С чего начать

1. Прочитай [README.md](README.md): что это и как устроено.
2. Команды, локальный запуск и тесты описаны в [CONTRIBUTING.md](CONTRIBUTING.md).
3. Деплой и настройки экземпляра описаны в [docs/self-hosting.md](docs/self-hosting.md). Для обычной доработки они не нужны.

## Как устроено

### Worker

Фронтенд и API живут на одном домене, поэтому CORS не нужен, а сессия хранится в cookie. Маршруты Worker'а:

- `/api/*`: REST;
- `/auth/telegram/*`: вход через Telegram;
- `/notion/oauth/*`: подключение Notion;
- `/tg/webhook`: обновления бота;
- остальное: статика фронтенда.

Cron срабатывает раз в минуту и запускает сначала напоминания бота, потом синк Notion (`src/cron.ts`).

В каждой таблице с данными пользователя есть `user_id`, и каждый запрос фильтрует по нему.

### Предметная область

- Задача может быть без проекта, в интерфейсе такие задачи собраны в группу "Без проекта".
- Проекты и задачи не удаляются, а уходят в архив. Архивация останавливает их таймеры. Удалить можно только сессию.
- Сессии одной задачи не пересекаются, сессии разных задач могут.
- Проекты и задачи сортируются по названию, "Недавние" по последнему запуску, архив по дате архивации.
- Напоминание о забытом таймере по умолчанию приходит через 3 часа.
- Язык нового пользователя берётся из браузера, потом меняется в настройках.

### Таймеры

- Таймер это сессия в `time_entries`: `started_at` и `ended_at`, у идущей `ended_at` пустой. Длительность считается из этих двух времён, счётчика нет.
- `started_at` и `ended_at` ставит сервер по своим часам. Фронтенд считает смещение по `X-Server-Now` и тикает на экране сам.
- У задачи идёт не больше одного таймера (уникальный индекс `time_entries_running_task_idx`). Всего одновременно идёт не больше 20 таймеров (`MAX_RUNNING_TIMERS`).
- Устройства видят изменения друг друга опросом: фронтенд перезапрашивает состояние при фокусе окна и раз в 20 секунд, пока вкладка видна (`apps/web/src/auto-refresh.ts`).
- Время хранится в UTC. Часовой пояс пользователя лежит в `users.timezone`, по нему сервер пишет даты в бот и в Notion.

### Вход и бот

- Вход только через Telegram OpenID Connect: Authorization Code с PKCE, `id_token` проверяется через `jose`. `state` одноразовый и живёт 10 минут.
- Сессия: случайный токен в cookie `stt_session`, в базе только его SHA-256. Живёт 30 дней и продлевается при активности.
- В `dev` и `test` есть `POST /auth/dev-login`: вход без Telegram.
- Бот получает обновления через webhook и отбрасывает запросы без верного заголовка `X-Telegram-Bot-Api-Secret-Token`.
- Команды бота: `/start`, `/status` и `/stop`. Напоминание о долгом таймере приходит с кнопками "Остановить" и "Ещё работаю".
- Бот пишет пользователю, только пока `users.bot_can_message` включён. Если пользователь заблокировал бота, флаг сбрасывается.

### Notion

- Пользователь подключает один workspace через OAuth и добавляет в трекер до 50 баз.
- Токены Notion зашифрованы AES-GCM ключом `TOKEN_ENC_KEY` и на клиент не уходят. На 401 трекер один раз обновляет токен. Если не вышло, подключение получает статус `needs_reauth`, и пользователь видит "Переподключить".
- Трекер не создаёт страницы в Notion. Синхронизируются только задачи со страницей: импортированные из базы и добавленные через "Добавить из Notion". Задачи с сайта живут только в трекере.
- Трекер не трогает поля пользователя. Он добавляет в базу свои поля и пишет только в них: `⏱ Затрачено, ч`, `⏱ Затрачено`, `⏱ Таймер идёт`, `⏱ Последний трек` и `⏱ Проект` (только когда проекты берутся из своего поля). Имена полей создаются на языке пользователя, а находятся на обоих языках.
- Время, сессии и заметки главнее в трекере. Название задачи и проект из поля пользователя синхронизируются в обе стороны, побеждает последнее изменение.
- Push: изменение задачи ставит её в очередь `sync_outbox`, одна строка на задачу. Cron отправляет запросы с паузой 350 мс, это ниже лимита Notion в 180 запросов в минуту. На 429 синк ждёт `Retry-After`, на другие ошибки повторяет с растущей задержкой до 60 минут. Пока таймер идёт, страница обновляется раз в 10 минут.
- Pull: раз в 5 минут трекер читает каждую базу по `last_edited_time` от своего курсора. Связанные страницы обновляют задачи, новые записи становятся задачами, кроме записей со статусами, которые пользователь пропускает. Страница в корзине отправляет задачу в архив.
- Блок на странице: callout "⏱ Всего: …" с журналом сессий в начале или в конце страницы. Трекер меняет его на месте, а удалённый вручную создаёт заново.

### Безопасность

- Чужие данные ведут себя как несуществующие, раздел "HTTP API" ниже.
- Текст из Notion и Telegram выводится как текст, `v-html` не используется.
- "Отключить Notion" удаляет токены. "Удалить аккаунт" удаляет все данные пользователя и отзывает токен Notion.

## Правила кода

- TypeScript strict, без `any`.
- Комментариев в коде нет. Понятность дают имена, маленькие функции и типы.
- В коде и тестах нет эмодзи, длинных тире и декоративных символов: стрелок, галочек, псевдографики.
- Простые модули с одной задачей, без лишних абстракций и дублирования.
- Входные данные API проверяют zod-схемы из `@stt/shared`.
- Другие пакеты импортируют из `@stt/shared` только то, что экспортирует `packages/shared/src/index.ts`.
- Форматирование: Prettier и ESLint, `npm run format` исправляет сам.

## HTTP API

- Префикс `/api`, JSON, поля в camelCase.
- ID: строки UUID. Несуществующий, чужой или неверный ID даёт 404. Чужие данные ведут себя как несуществующие.
- Время: ISO 8601 UTC с миллисекундами, например `2026-10-31T12:00:00.000Z`. Длительности: целые секунды, поля с суффиксом `Sec`.
- Каждый ответ содержит заголовок `X-Server-Now` с серверным временем. Фронтенд считает таймеры по нему.
- `PATCH` без единого известного поля даёт 400.
- Ошибка: `{ "error": { "code": "...", "message": "...", "details": { ... } } }`. `message` на английском и пользователю не показывается: интерфейс показывает свой текст по `code`.
- Изменяющий запрос с чужим `Origin` даёт 403 `forbidden`.

## Тексты и языки

- Все тексты для людей лежат в `packages/shared/src/i18n/ru.ts` и `en.ts`. Набор ключей в них одинаковый, пустых строк нет.
- Текст с числом хранится одной строкой с формами через `|`: в `ru` три формы, в `en` две. Подставляет его `tc`.
- Интерфейс обращается к пользователю на "ты".
- Тема только светлая. Цвета трекера заданы токенами в `apps/web/src/styles/main.css` поверх дизайн-системы OpenKEGE.

## База данных

- Схема в `apps/api/src/db/schema.ts`. Миграцию по ней создаёт `npm run db:generate -w @stt/api`.
- Миграции только добавляются вперёд. Старый код должен работать с новой схемой: откат Worker'а базу не трогает.

## Тесты

- API: `apps/api/test/**/*.test.ts`, идут внутри рантайма Workers. Обвязка в `apps/api/test/harness` перехватывает внешние запросы к Telegram и Notion. Незарегистрированный внешний запрос роняет тест.
- Чистые функции: `packages/shared/test/**/*.test.ts`.
- UI: `apps/web/e2e/**/*.spec.ts`. Элементы ищут по роли и видимому тексту (`getByRole`, `getByLabel`, `getByText`), а не по классам или `data-testid`. Каждый тест входит под своим уникальным пользователем.
- Тесты описывают поведение, а не реализацию. Если тест падает, сначала разберись, кто прав, и не подгоняй тест под код.
- Новая функция приходит с тестами.

## Когда работа готова

Проходят все четыре команды:

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
```

Полный прогон e2e на слабой машине иногда падает из-за нагрузки. Упавшие файлы перезапусти отдельно, например `npx playwright test e2e/<файл>.spec.ts` из `apps/web`.

## Git

- Работа идёт в ветке от свежего `main`, PR в `main`.
- Агент не коммитит, не пушит и не открывает PR без просьбы человека.
- Секреты и файлы `.dev.vars` в git не попадают.
