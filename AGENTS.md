# Онбординг агента

Этот файл для ИИ-агентов, которые пишут код в репозитории. Людям те же правила нужны при доработках: [CONTRIBUTING.md](CONTRIBUTING.md) ссылается сюда.

SimpleTimeTracker: трекер времени по задачам и проектам. Вход через Telegram, синк с Notion, Telegram-бот, PWA. Один Cloudflare Worker отдаёт API и фронтенд, данные лежат в D1.

## С чего начать

1. Прочитай [README.md](README.md): что это и как устроено.
2. Команды, локальный запуск и тесты описаны в [CONTRIBUTING.md](CONTRIBUTING.md).
3. Деплой и настройки экземпляра описаны в [docs/self-hosting.md](docs/self-hosting.md). Для обычной доработки они не нужны.

## Где что лежит

npm workspaces, Node 22.12 или новее.

```
apps/api                Cloudflare Worker на Hono (@stt/api)
  src/routes            HTTP-маршруты, по файлу на ресурс
  src/projects, tasks, timers, users, notion, sync, telegram
                        логика по предметным областям
  src/db/schema.ts      схема Drizzle
  src/http              общее для HTTP: проверка входных данных, Origin, ошибки, время, лимит запросов
  src/cron.ts           работа по cron: синк Notion и напоминания
  migrations/           миграции D1, генерируются из схемы
  scripts/              деплой, настройка бота, бэкап
  test/                 Vitest-тесты API, обвязка в test/harness
  wrangler.jsonc        конфиг Worker'а и окружений
apps/web                фронтенд на Vue 3 и Vite (@stt/web)
  src/pages             страницы роутера
  src/components        компоненты, базовые в components/ui
  src/stores            Pinia
  src/styles/main.css   тема трекера поверх дизайн-системы
  src/design/openkege   дизайн-система OpenKEGE, вендорная копия, не править
  e2e/                  Playwright-тесты, хелперы в e2e/helpers
packages/shared         общий код (@stt/shared)
  src/index.ts          публичный интерфейс пакета
  src/i18n/ru.ts, en.ts словари интерфейса, бота и Notion
  test/                 Vitest-тесты чистых функций
```

## Правила кода

- TypeScript strict, без `any`.
- Комментариев в коде нет. Понятность дают имена, маленькие функции и типы.
- В коде и тестах нет эмодзи, длинных тире и декоративных символов: стрелок, галочек, псевдографики.
- Простые модули с одной задачей, без лишних абстракций и дублирования.
- Входные данные API проверяют zod-схемы из `@stt/shared`.
- Другие пакеты импортируют из `@stt/shared` только то, что экспортирует `packages/shared/src/index.ts`.
- Форматирование: Prettier и ESLint, `npm run format` исправляет сам.

## HTTP API

- Префикс `/api`, JSON, поля в camelCase.
- ID: строки UUID. Несуществующий, чужой или неверный ID даёт 404. Чужие данные ведут себя как несуществующие.
- Время: ISO 8601 UTC с миллисекундами, например `2026-10-31T12:00:00.000Z`. Длительности: целые секунды, поля с суффиксом `Sec`.
- Каждый ответ содержит заголовок `X-Server-Now` с серверным временем. Фронтенд считает таймеры по нему.
- `PATCH` без единого известного поля даёт 400.
- Ошибка: `{ "error": { "code": "...", "message": "...", "details": { ... } } }`. `message` на английском и пользователю не показывается: интерфейс показывает свой текст по `code`.
- Изменяющий запрос с чужим `Origin` даёт 403 `forbidden`.

## Тексты и языки

- Все тексты для людей лежат в `packages/shared/src/i18n/ru.ts` и `en.ts`. Набор ключей в них одинаковый, пустых строк нет.
- Текст с числом хранится одной строкой с формами через `|`: в `ru` три формы, в `en` две. Подставляет его `tc`.
- Интерфейс обращается к пользователю на "ты".
- Тема только светлая. Цвета трекера заданы токенами в `apps/web/src/styles/main.css` поверх дизайн-системы OpenKEGE.

## База данных

- Схема в `apps/api/src/db/schema.ts`. Миграцию по ней создаёт `npm run db:generate -w @stt/api`.
- Миграции только добавляются вперёд. Старый код должен работать с новой схемой: откат Worker'а базу не трогает.

## Тесты

- API: `apps/api/test/**/*.test.ts`, идут внутри рантайма Workers. Обвязка в `apps/api/test/harness` перехватывает внешние запросы к Telegram и Notion. Незарегистрированный внешний запрос роняет тест.
- Чистые функции: `packages/shared/test/**/*.test.ts`.
- UI: `apps/web/e2e/**/*.spec.ts`. Элементы ищут по роли и видимому тексту (`getByRole`, `getByLabel`, `getByText`), а не по классам или `data-testid`. Каждый тест входит под своим уникальным пользователем.
- Тесты описывают поведение, а не реализацию. Если тест падает, сначала разберись, кто прав, и не подгоняй тест под код.
- Новая функция приходит с тестами.

## Когда работа готова

Проходят все четыре команды:

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
```

Полный прогон e2e на слабой машине иногда падает из-за нагрузки. Упавшие файлы перезапусти отдельно, например `npx playwright test e2e/<файл>.spec.ts` из `apps/web`.

## Git

- Работа идёт в ветке от свежего `main`, PR в `main`.
- Агент не коммитит, не пушит и не открывает PR без просьбы человека.
- Секреты и файлы `.dev.vars` в git не попадают.
