# Контракт для спецификаций и тестов

Правила действуют во всех шагах. Спецификация шага может их дополнять, но не отменять.

Шаг это issue на доске [SimpleTimeTracker](https://github.com/users/CompleWin/projects/3). Его название начинается с ключа `STT-N`, где N это номер issue, а спецификация лежит в теле issue.

Устройство системы, правила кода, API, текстов, базы и тестов описаны в [AGENTS.md](../AGENTS.md), дизайн интерфейса в [docs/design/](design/). Здесь только то, чего там нет.

## Контракт API

- JSON в UTF-8.
- Входящее время принимается в любом ISO-формате со смещением и нормализуется. Длительности округляются вниз.
- `X-Server-Now` есть в каждом ответе сервера, включая ошибки, статику и редиректы.
- Коды успеха: 200 на чтение и изменение, 201 на создание, 202 на работу, поставленную в очередь, 204 на ответ без тела.
- Невалидный JSON в теле даёт 400 `validation_error`.
- Ответы могут содержать поля сверх описанных. Тесты проверяют только описанные поля через `toMatchObject`.
- `details` в ошибке есть не всегда. У `validation_error` в `details.fields` перечислены поля с проблемами:

```json
{
  "error": {
    "code": "validation_error",
    "message": "...",
    "details": { "fields": { "name": "..." } }
  }
}
```

| HTTP | `code`                   | Когда                                            |
| ---- | ------------------------ | ------------------------------------------------ |
| 400  | `validation_error`       | тело, параметры или заголовки не прошли проверку |
| 401  | `unauthorized`           | нет сессии или она истекла                       |
| 403  | `forbidden`              | изменяющий запрос пришёл с чужого `Origin`       |
| 404  | `not_found`              | ресурса нет или он чужой                         |
| 409  | `name_taken`             | проект с таким названием уже есть                |
| 409  | `already_running`        | у задачи уже идёт таймер                         |
| 409  | `not_running`            | таймер не идёт                                   |
| 409  | `task_archived`          | задача или её проект в архиве                    |
| 409  | `too_many_running`       | уже идут 20 таймеров                             |
| 409  | `overlap`                | сессия пересекается с другой сессией этой задачи |
| 409  | `notion_reauth_required` | Notion нужно переподключить                      |
| 409  | `property_conflict`      | конфликт имени или типа колонки Notion           |
| 409  | `database_already_added` | эта база уже добавлена в трекер                  |
| 409  | `too_many_databases`     | добавлено 50 баз                                 |
| 409  | `already_linked`         | страница Notion уже связана с задачей            |
| 429  | `rate_limited`           | слишком много запросов                           |
| 502  | `notion_unavailable`     | Notion не ответил или ответил ошибкой сервера    |

### Авторизация

- Все `/api/*`, кроме `/api/health`, требуют сессию, иначе 401. Неизвестный маршрут `/api/*` без сессии даёт 401, с сессией 404.
- Ссылка на чужой ресурс в теле запроса даёт 400 с указанием поля.
- Изменяющие запросы (всё, кроме GET и HEAD) с заголовком `Origin`, который не совпадает с origin `APP_URL`, получают 403 `forbidden`. Запросы без `Origin` разрешены.

### Удаление задачи во время синхронизации с Notion

`DELETE /api/tasks/:id` удаляет задачу, её сессии и запись из очереди синхронизации. Как только удаление зафиксировано в базе, API возвращает 204, даже если Notion ещё обрабатывает запрос по этой задаче.

Перед каждым запросом на изменение страницы или блока «⏱ Всего» трекер проверяет в базе, что задача существует и всё ещё связана с этой страницей. Если задача удалена или связь изменилась, трекер пропускает запрос. Запрос, прошедший проверку до удаления, может завершиться после ответа 204. Для следующего изменения и для каждой повторной попытки трекер проверяет связь заново.

Следующий запуск cron сохраняет результат удаления. Задача и запись в очереди не появляются снова, трекер не отправляет новых изменений на страницу или в её блоки.

## Окружения

Переменная `ENV`: `dev` (локальная разработка и e2e), `test` (Vitest), `staging`, `production`.

Для индексации открыты только публичные страницы в `production`. В остальных окружениях `robots.txt` запрещает обход сайта, а HTML-страницы содержат `noindex`.

### Тестовые механизмы

В `staging` и `production` они выключены: заголовок игнорируется, эндпоинты отвечают 404.

| Механизм                      | Где работает  | Что делает                                                                                                                                     |
| ----------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| заголовок `X-Test-Now: <ISO>` | `test`        | подменяет "сейчас" для всего запроса, включая запущенную им фоновую работу. Неверное значение даёт 400 `validation_error` с полем `X-Test-Now` |
| `POST /__test/cron`           | `test`        | синхронно выполняет ту же работу, что и cron, с учётом `X-Test-Now`, и отвечает 204 после её завершения                                        |
| `POST /auth/dev-login`        | `dev`, `test` | вход без Telegram                                                                                                                              |

### Переменные и секреты

| Имя               | Что это                                   |
| ----------------- | ----------------------------------------- |
| `ENV`             | окружение                                 |
| `TG_OAUTH_BASE`   | по умолчанию `https://oauth.telegram.org` |
| `TG_API_BASE`     | по умолчанию `https://api.telegram.org`   |
| `NOTION_API_BASE` | по умолчанию `https://api.notion.com`     |

Остальные переменные и секреты описаны в [self-hosting.md](self-hosting.md). В `test` `APP_URL` равен `https://stt.test`, а `NOTION_WEBHOOK_SECRET` равен `test-notion-webhook-secret`.

Внешние HTTP-запросы идут только на адреса из `*_BASE`. В тестах значения секретов фиксированы и видны через обвязку (`testEnv`).

## Языки

- Словари `@stt/shared`: `messages: Record<Locale, Messages>`, `t(locale, key, params?)` с подстановкой `{name}`, `tc(locale, key, count, params?)` для текстов с числом. Фронтенд подключает их через vue-i18n, Worker использует напрямую.
- `tc` выбирает форму по `Intl.PluralRules` языка. Пример: `{count} сессия|{count} сессии|{count} сессий` и `{count} session|{count} sessions`.
- Язык вошедшего пользователя хранится в `user.locale`. На нём сервер пишет в бот и в Notion.
- До входа язык берётся из `navigator.language`: `ru*` даёт `ru`, остальное `en`. Выбор в меню шапки гостевой главной запоминается в `localStorage`.
- На `/ru` и `/en` язык гостевого лендинга задаёт адрес. Этот язык запоминается в `localStorage`. У вошедшего пользователя эти адреса ведут на `/`, сохраняя язык профиля.
- Для HTML с сервера на `/ru` и `/en` язык задаёт адрес. На остальных страницах Worker применяет то же правило к первому языку из `Accept-Language`. Без заголовка выбирает `en`.

## Форматы

Длительности: `formatDuration(sec, locale)` и `formatClock(sec)`. Даты: `formatDate`, `formatDateTime`, `formatShortDate`, `formatTime`, `formatWeekdayDate`, `formatWeekdayShort`, `formatDayMonth`, `formatMonthYear`, `formatWeekRange`. Все из `@stt/shared`, всегда в часовом поясе пользователя.

| Что                 | ru                | en                  |
| ------------------- | ----------------- | ------------------- |
| дата                | 31.10.2026        | Oct 31, 2026        |
| дата и время        | 31.10.2026 14:32  | Oct 31, 2026 14:32  |
| короткая дата       | 31.10             | Oct 31              |
| время               | 14:32             | 14:32               |
| день недели и дата  | вторник, 3 ноября | Tuesday, November 3 |
| день недели коротко | вт                | Tue                 |
| день и месяц        | 31 октября        | October 31          |
| месяц и год         | Ноябрь 2026       | November 2026       |

Диапазон недели показывает даты понедельника и воскресенья. В одном месяце название месяца пишется один раз, например "9–15 ноября". На границе года видны оба года.

## Решения

- Пользователям из России для трекера нужен VPN, как и для самого Notion. Хостинг остаётся на Cloudflare, вход через Telegram. Аудитория в России без VPN потребовала бы хостинга в РФ и другого входа, а Notion ей всё равно недоступен.

## Правила для e2e-контракта

- Видимые тексты и элементы только из спецификации шага.
- Капс только через CSS `uppercase`. В словарях и DOM текст хранится в регистре контракта: "Сейчас идёт", а не "СЕЙЧАС ИДЁТ".
- Элемент с контрактным текстом не дублируется внутри одного контейнера.
- Одна задача может стоять в нескольких местах панели выбора. Поэтому каждый раздел панели и каждый раскрытый проект в дереве это группа (`role="group"`) с именем, и тест ищет строку внутри группы.
- Контрактные элементы видны на любой ширине. Кликом открываются только меню "Меню" у аватара, панель выбора задачи (и на главной, и в диалоге "Новая сессия"), календарь "Хронологии", поле "Заметка: …" идущего таймера (кнопкой "Написать заметку: …"), меню действий и диалоги. Ручка "Изменить размер панели" есть только от 768 px.
- Радиокнопки, оформленные чипами, остаются настоящими `input type="radio"`, скрытыми через `sr-only`, а не `display: none`.
- У кнопки-иконки доступное имя из `aria-label`, `title` с ним совпадает. "Старт" и "Стоп" это кнопки-иконки, слово живёт только в `aria-label` и `title`.
- Если доступное имя кнопки задано `aria-label`, видимый текст внутри может быть другим.
- Строка, которую проверяет критерий, стоит в DOM одним текстовым узлом: "Всего: 2 ч 5 мин". Числа со склонением собирает `tc`.
- Разделитель " · " хранится в словарях вместе с текстом.
- У каждого поля формы видимая подпись `<label>`. Без неё, только с `aria-label`, живут поиск в панели выбора, поле заметки идущего таймера, поиск на странице "Задачи" и флажки строк "Выбрать: <название>".
- У каждой кнопки есть текст или `aria-label`. У каждого диалога роль `dialog`, заголовок и кнопка-крестик "Закрыть", у диалога подтверждения ещё "Отмена".
